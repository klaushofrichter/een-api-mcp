Overview

This document outlines the implementation plan for an MCP (Model Context Protocol) server that provides AI assistants with access to Eagle Eye Networks (EEN) camera systems. The server enables querying cameras, fetching live/recorded images, accessing events, and managing users.

Design Principles

1. No External Proxy Token management is local to the server
2. Multi-User Support Credentials stored per account name
3. No Vue/Pinia Direct REST API calls using fetch
4. Headless Auth Playwright-based OAuth automation
5. Modular Design Independent components for parallel dev

Authentication Strategy

Design Decision: Authentication is performed separately via CLI. Users must authenticate accounts before using the MCP server through Claude. This ensures passwords never flow through AI conversations.

Auth CLI Commands

# Login and store credentials
npx tsx cli/auth.ts login \
  --username user@example.com \
  --password "your-password" \
  --client-id "your-client-id" \
  --client-secret "your-client-secret" \
  [--persistPassword]                    # Optional: enable auto-reauth

# List configured accounts
npx tsx cli/auth.ts list

# Show detailed account status
npx tsx cli/auth.ts status

# Revoke tokens and remove account
npx tsx cli/auth.ts revoke --account user@example.com

Two-Phase Authentication

Phase 1: Credential Acquisition (CLI)

  1. Launch headless Chromium via Playwright
  2. Navigate to EEN OAuth URL
  3. Automate login form
  4. Capture authorization code
  5. Exchange code directly with EEN
  6. Store tokens locally
  7. Optionally encrypt and store password

Phase 2: MCP Server Runtime

  1. Load credentials on startup
  2. No account active initially
  3. User must call een_set_account
  4. API calls require active account
  5. Auto-refresh using refresh token
  6. If refresh fails + password → re-auth
  7. If refresh fails + no password → error

Token Refresh Flow

ensureValidToken(account) │ ├─► Token valid? → Return success │ ├─► Try refreshAccessToken() │ │ │ ├─► Success → Update storage, return success │ │ │ └─► Failure (refresh token expired) │ │ │ ├─► Password stored? → reAuthenticate() │ │ ├─► Success → Update all tokens │ │ └─► Failure → AUTH_FAILED error │ │ │ └─► No password → AUTH_EXPIRED error │ (User must run CLI to re-authenticate)

Note: No default account. Users must call een_set_account before making API calls.

Security: File permissions 0o600. Passwords encrypted using machine-specific key. Trade-off: --persistPassword enables convenience but stores credentials locally.

Direct API Integration

HTTP Client Design

All API calls use native fetch() with Bearer token authentication:

async function eenFetch<T>(
  endpoint: string,
  options: RequestInit = {}
): Promise<Result<T>> {
  const account = getActiveAccount()

  // Auto-refresh if needed
  if (isTokenExpired(account)) {
    const refreshResult = await refreshAccessToken(account)
    if (refreshResult.error) return refreshResult
  }

  const response = await fetch(
    `${account.baseUrl}/api/v3.0${endpoint}`,
    {
      ...options,
      headers: {
        'Accept': 'application/json',
        'Authorization': `Bearer ${account.accessToken}`,
        ...options.headers
      }
    }
  )

  if (!response.ok) {
    return { data: null, error: parseError(response) }
  }

  return { data: await response.json(), error: null }
}

Token Refresh Implementation

async function refreshAccessToken(account: Account): Promise<Result<void>> {
  const response = await fetch(
    'https://auth.eagleeyenetworks.com/oauth2/token',
    {
      method: 'POST',
      headers: {
        'Content-Type': 'application/x-www-form-urlencoded',
        'Authorization': `Basic ${base64(CLIENT_ID + ':' + CLIENT_SECRET)}`
      },
      body: new URLSearchParams({
        grant_type: 'refresh_token',
        refresh_token: account.refreshToken
      })
    }
  )

  if (!response.ok) {
    return { data: null, error: { code: 'AUTH_FAILED' } }
  }

  const data = await response.json()

  // Update stored credentials
  account.accessToken = data.access_token
  account.accessTokenExpiresAt = Date.now() + (data.expires_in * 1000)
  if (data.refresh_token) {
    account.refreshToken = data.refresh_token  // Token rotation
  }

  await saveCredentials()
  return { data: undefined, error: null }
}

Security Considerations

1. Credential Storage

  • All credentials in ~/.een-mcp/credentials.json with 0o600 permissions
  • Refresh tokens stored in plaintext (standard for local credential files)
  • Client ID/secret stored once, reused for all accounts
  • Never logged or exposed via MCP responses

2. Password Persistence (--persistPassword)

  • Passwords encrypted at rest using machine-specific key
  • Enables automatic re-authentication when refresh token expires
  • Trade-off: Convenience vs. security - users should understand the risk
  • Without flag: User must manually re-run CLI when refresh token expires
  • With flag: MCP server can silently re-authenticate

3. Token Lifecycle

  • Auto-refresh 5 min before expiry
  • Refresh token rotation supported
  • Failed refresh → reauth or error

4. Token Revocation

  • revoke calls EEN revocation endpoint
  • Removes all local data (tokens + password)
  • Ensures tokens cannot be reused

5. Input Validation

  • All parameters validated
  • Pagination limits enforced
  • Timestamp format validation

6. MCP Server Isolation

  • Passwords never flow through MCP
  • Users authenticate via CLI separately
  • MCP tools only read existing credentials
